# РУКОВОДСТВО ПО УЧАСТИЮ В ПРОЕКТЕ

Спасибо за интерес к проекту! Это руководство поможет вам внести вклад.

## 🎯 Как внести вклад

### Сообщения об ошибках

Если вы нашли ошибку:
1. Проверьте, не была ли она уже зарегистрирована в Issues
2. Создайте новую Issue с описанием проблемы
3. Укажите шаги для воспроизведения ошибки
4. Приложите скриншоты или примеры кода, если возможно

### Предложения по улучшению

Если у вас есть идея по улучшению:
1. Создайте Issue с описанием предложения
2. Объясните, почему это улучшение полезно
3. Предложите способ реализации (если возможно)

### Pull Requests

1. Fork репозитория
2. Создайте ветку для ваших изменений (`git checkout -b feature/AmazingFeature`)
3. Внесите изменения
4. Убедитесь, что код работает и соответствует стилю проекта
5. Commit изменения (`git commit -m 'Add some AmazingFeature'`)
6. Push в вашу ветку (`git push origin feature/AmazingFeature`)
7. Откройте Pull Request

## 📝 Стандарты кода

### Python
- Следуйте PEP 8
- Используйте понятные имена переменных
- Добавляйте комментарии к сложным участкам кода
- Добавляйте docstrings к функциям

### Jupyter Notebooks
- Очищайте вывод перед коммитом
- Используйте markdown ячейки для объяснений
- Группируйте связанные ячейки

### Документация
- Пишите на русском языке
- Используйте Markdown для форматирования
- Добавляйте примеры использования

## 🧪 Тестирование

Перед отправкой Pull Request:
- Убедитесь, что код работает
- Проверьте, что не сломали существующую функциональность
- Если возможно, добавьте тесты для новой функциональности

## 📚 Документация

При добавлении новой функциональности:
- Обновите README.md, если необходимо
- Добавьте документацию в соответствующие файлы в `docs/`
- Обновите примеры использования

## 🤝 Процесс ревью

После отправки Pull Request:
- Изменения будут проверены
- Могут быть запрошены дополнительные изменения
- После одобрения изменения будут объединены

## ❓ Вопросы?

Если у вас есть вопросы, создайте Issue с меткой "question".
